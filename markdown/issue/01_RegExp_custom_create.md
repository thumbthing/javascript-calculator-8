# RegExp custom create

---

## 발생 원인

기본 구분자 `, :` 과 선택사항인 커스텀 구분자로 인해 사용자의 입력값을 배열로 분리해서 기능을 구현하기로 계획함.  
구분자들의 패턴으로 정의할 정규표현식을 작성하는 과정에서 패턴의 변동 가능성이 존재했기 때문에 기존에 익숙했던 literal 방식으로는 유동적인 정규식을 생성하는 것이 제한되었음.  
  
정규식을 작성하는 방식에는 두가지가 존재  

1. literal
2. constructor

### literal

#### 작성 예시

```javascript

const regex = /여기에 패턴을 작성한다/

```

### constructor

#### 작성 에시

```javascript

const regex = new RegExp('여기에 패턴을 작성')

```

### 차이점

| 구분           | 리터럴 방식 (literal)       | 생성자 방식 (constructor)             |
| ------------ | ---------------------- | -------------------------------- |
| **형식**       | `/pattern/flags`       | `new RegExp('pattern', 'flags')` |
| **평가 시점**    | 코드 작성 시점(compile time) | 런타임(run time)                    |
| **이스케이프 처리** | 문자열 내 escape 불필요       | 문자열이므로 `\\`로 escape 필요           |
| **동적 생성**    | 불가능                    | 가능                               |
| **가독성**      | 간결하고 명확                | 복잡하지만 유연                         |
| **성능**       | 약간 빠름 (컴파일 시점에 미리 파싱)  | 런타임 생성으로 약간 느림                   |

---

## 결론

기본적으로는 literal 방식으로 선언하여 가독성-성능을 챙기긴 하지만 동적으로 생성을 할 필요가 있을때는 constructor로 생성하는 방식으로 사용
